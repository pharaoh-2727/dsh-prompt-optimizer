# 用法

所有入口共用同一份改写引擎（`optimizeText()`），所以从哪儿进来，档位复核、过度扩写兜底、免费通道回退、结果结构都一模一样。

## 六个入口

| 入口 | 谁用它 | 结果去哪 |
|---|---|---|
| 输入框右侧 ✨ | 人 | 预览卡 → 确认后写回输入框 |
| 会话标题旁 ✨ | 人（手在标题栏附近） | 同上 |
| **Alt+O** | 人（键盘党） | 同上；**已有结果时按一下 = 采用** |
| `/optimize <文字>` | 人 / 脚本 | 命令回执进对话 |
| 光敲 `/optimize` | 人（已写好草稿） | 预览卡 → 写回输入框 |
| `optimize_prompt` 工具 | **模型** | 工具返回值给模型 |
| `promptOptimizer` 服务 | **别的插件** | 返回 Promise |

为什么要这么多入口：按钮只活在浏览器里 —— 脚本调不到它，别的插件调不到它，模型自己也调不到它。命令给人和脚本用，工具给模型用，服务给插件用，三者共用同一条实现。

### Alt+O 的状态语义

同一个键不产生第二种含义：

- 预览卡里有结果 → **采用**它
- 正在生成 → 什么都不做
- 草稿非空 → 优化它
- 草稿为空 → **不吞键**（放给宿主或别的插件）

输入法组合中（`isComposing`）与带 Ctrl/Shift/Meta 时不触发。

## 预览卡

结果**不会直接盖住你的输入** —— 输入框上方弹出预览卡，你点「替换草稿」才写回。

| 按钮 | 作用 |
|---|---|
| **替换草稿** | 写回输入框；写回后按钮变成「退回」，还能一键还原 |
| **复制** | 放进剪贴板，不动输入框 |
| **重新优化** | 用当前输入框里的内容再跑一次 |
| **放弃** | 关掉预览卡，输入框保持原样 |
| **历史 N**（标题行右侧） | 展开之前优化过的几版 |

优化进行中按钮显示「优化中」，失败时上方弹出原因，5 秒后自动消失。输入框为空时按钮不可点。

### 流式

模型每吐一段字，预览卡就更新一次：标题写「生成中…」，正文逐段出现，思考过程单独显示在「思考过程」小框里，不跟正文混在一起。生成过程中「替换草稿」是灰的，「取消」随时可点。

服务端用 SSE：`start` → `reasoning` → `delta`（多次）→ `done`。三种情况退回一次性接口：宿主没有 `/stream` 路由（旧版宿主）、代理把 SSE 改成了普通 JSON、拿不到可读流。

### 用量与用时

标题下面一行小字：**用时**（如 `1.2s`）、**token**（如 `50 token`）、**字数**（如 `86 字`）。模型没给 token 用量时写「token 未提供」，**不会写 0 冒充数据**。

### 缩放

整张预览卡就是一个可改大小的窗口：

- **位置固定**在输入框正上方，没有位移交互
- **高度可调**：卡片上沿浮着一条高度手柄，拖它改高度；也可聚焦后按 ↑/↓，每次 24px
- 高度范围 160 ~ 720px，并按视口剩余高度收口 —— 上沿顶到离窗口顶部 16px 就停
- **宽度可调**：左右两侧各一条边缘手柄，左右互不影响；每侧最多外扩 240px，往里最多收到原宽 40%；键盘 ←/→ 每次 24px
- 手柄默认透明，鼠标移上去 / 拖动 / 聚焦时才显现
- 大小记在 localStorage（`dsho.preview.body-height` / `dsho.preview.body-width`），下次打开还是这个大小

## 历史版本与对比

每次优化成功都会留一版，存在浏览器 localStorage（键名 `dsho.preview.history`），**最多 20 条**，超出的从最旧的开始丢。

- 标题行最右边「**历史 N**」按钮，N 是攒下来的版数；没有历史时不显示
- 点开是倒序列表：时间 · 档位 · 过程标签 · 正文摘要
- 过程标签说明这一版经历了什么：`已收敛`（写超了、按上限删短过）、`已补齐`（只改了措辞、按下限补写过）、`已拉回`（一句话被扩成文档、已改回克制写法）、`免费通道`（这一版由免费通道生成）
- **点某一行** → 正文换成那一版，顶部挂横幅「正在看 13:42 那版历史（不是当前结果）」，主按钮变成「**用这一版**」
- 行尾「**对比**」→ 和正在看的那一版左右并排，逐行标出改动（左红右蓝）
- 「**删除**」只删这一条；列表顶部「**清空**」一次清掉全部
- 「**回到当前结果**」退出历史视图

边界情况是特意处理过的：新的一次优化自动退出历史视图；看历史时「复制」复制的是你看的那一版；对比用逐行 LCS，两版行数乘起来超过 40 万就退回「并排但不标色」；卡片拖过高度后历史列表改成盖在卡片里的浮层，不再把正文挤成一行。

## 对比原文

预览卡动作栏里的「**对比原文**」：左边是你原来写的那句、右边是优化结果，逐行标出改了哪些字。原文和结果完全一样时这个按钮不出现。

## 编辑冲突保护

优化要等模型返回，这期间你如果又改了输入框，这份结果**不会覆盖你新写的内容**：

- 顶部出现提示「你在等待期间改过输入框，这份结果不会覆盖你新写的内容」
- **「替换草稿」被禁用**
- 想用这份结果可以点「复制」拿走，或者点「重新优化」基于最新输入再跑一次

这个检查是**实时**的：结果出现之后你再动输入框，按钮同样会立刻变灰。

## 取消

优化进行中按钮变成「**取消**」（图标变成方块）：点一下立刻中止，不再等模型回话；中止后按钮回到「优化」，**不弹红色错误**（取消是你主动的，不是故障）；输入框内容原样保留。

## 「优化 / 退回」两态

采用结果写回输入框后，同一个按钮自动变成「**退回**」：

| 状态 | 按钮 | 点下去 |
|---|---|---|
| 未优化 | **优化** ✨ | 调用模型改写，结果进预览卡 |
| 优化中 | 优化中（旋转） | 可点 = 取消这次优化 |
| 结果在预览卡里 | **优化** ✨ | 再跑一次 |
| 已采用结果 | **退回** ↩ | 把输入框恢复成优化前的原文 |

一旦你又动了输入框（追加、修改、手动改回原文），按钮立刻变回「优化」——「退回」只对当前这一次优化有效。

## 设置

「设置 → 优化」里有：

- **力度**：精简 / 均衡 / 详细 / 自定义（自定义留空则回退到均衡）
- **优化用的模型**：自动 / 免费通道 / 手动
- **免费通道连通性**：选中免费通道后发一句 `Hi` 端到端验证，显示耗时和回复；点「重新测试」强制真去请求一次（跳过缓存）
- **上次实际调用**：代码记录的最近一次真实路由，用来核实模型（模型自述自己是谁并不可靠）
